# 发布恢复

正式发布只通过本仓库 `.github/workflows/release.yml`，按标签只读检出私有源码。客户端源码不会存入本仓库。

`artifacts_run_id` 仅用于 GitHub 上传失败后的恢复。来源必须是本仓库已完成的标准手动发布任务，四个平台构建均成功、资产未过期，并从源码解析任务日志核对相同私有标签及完整 commit。重新下载原签名产物后，仍运行全部包格式、签名、版本、清单和 Sparkle 校验，不重新签名或修改包。

新版本先创建草稿，逐项上传并重试网络失败，核对唯一名称、完整数量、大小及 GitHub 提供的 SHA-256。全部通过后才公开并设为最新版本。上传失败保留草稿，不改变公开 OTA；恢复时只在工作流内替换草稿资产。已经公开的版本只校验，不覆盖内容。

验证：`node --test scripts/release.test.mjs`。客户端源码中的发布验证继续负责每种安装格式、真实签名、固定公钥和更新流程的回归检查。
